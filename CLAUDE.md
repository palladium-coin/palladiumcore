# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Palladium Core (v2.x) is a Bitcoin Core fork in C++11 with Taproot (BIP340/341/342) support. Source layout, subsystem boundaries, and conventions follow upstream Bitcoin Core, with `bitcoin` renamed to `palladium` everywhere (`palladiumd`, `palladium-cli`, `palladium-qt`, `palladium-tx`, `palladium-wallet`, `test_palladium`, `libpalladium_*.a`, `palladium.conf`, default datadir `~/.palladium`). `doc/developer-notes.md` is the coding-style reference.

## Build

Autotools. Bootstrap and build:

```bash
./autogen.sh
./configure            # add --without-gui, --disable-wallet, --with-incompatible-bdb, etc. as needed
make -j$(nproc)
```

- `./quick-build.sh [--build|--rebuild|--clean|--install-deps|--install-db]` is an Ubuntu 20.04/WSL helper that installs deps + BerkeleyDB 4.8 and builds with ccache. `--rebuild` is the fast incremental path; `--build` reconfigures.
- Reproducible/release builds: `docker-build/` (`build-menu.sh`, per-target `build-linux-*.sh` / `build-windows.sh`). Cross-compilation uses `depends/` and requires an explicit `--host=` in configure.
- Outputs: `src/palladiumd`, `src/palladium-cli`, `src/qt/palladium-qt`, `src/test/test_palladium`.
- `build_msvc/` holds Windows MSVC project files (still named `bitcoin*` in places).
- `update_version.sh` bumps version strings.

## Testing

```bash
make check                                              # unit tests + util tests
src/test/test_palladium --run_test=<suite>              # one Boost suite (e.g. pow_tests)
src/test/test_palladium --run_test=<suite>/<case>       # one case
test/functional/test_runner.py                          # all functional tests
test/functional/feature_block.py                        # one functional test (standalone Python)
test/functional/test_runner.py --jobs=4 <name>.py       # selected tests in parallel
test/lint/lint-all.sh                                   # lint suite 
```

- Unit tests: `src/test/*_tests.cpp` (Boost.Test); fuzz harness is `test/fuzz/test_runner.py` (built via `src/Makefile.test_fuzz.include`). Benchmarks: `src/bench`.
- Functional tests need a built tree; `test/config.ini` is generated by configure. The Python framework (`test/functional/test_framework/`) spawns `palladiumd` and wraps `palladium-cli`.
- Build system is split into `src/Makefile*.include` fragments (`Makefile.test.include`, `Makefile.qt.include`, ...); new source files must be added to the relevant `.include` list or they will not be built.

## Architecture

Library layering (defined in `src/Makefile.am`), lowest to highest — respect it; `test/lint/lint-circular-dependencies.sh` enforces no include cycles:

- `libpalladium_consensus` — consensus-critical code only (`src/consensus/`, script, primitives, pow.cpp helpers). Also exposed as `libpalladiumconsensus` (`libpalladiumconsensus.pc.in`).
- `libpalladium_util`, `libpalladium_crypto_*` (SSE4.1/AVX2 variants built separately), `libpalladium_common` — shared utilities, key/address handling, chain params.
- `libpalladium_server` — node: `init.cpp` (startup/shutdown wiring), `validation.cpp` (chainstate, mempool acceptance, block connect), `net.cpp` / `net_processing.cpp` (P2P), `txmempool.cpp`, `miner.cpp`, RPC (`src/rpc/`, `httprpc.cpp`, `httpserver.cpp`), indexes (`src/index/`), `libpalladium_zmq` for notifications.
- `libpalladium_wallet` (+ `_wallet_tool`) — `src/wallet/`, BDB and descriptor wallets; `dummywallet.cpp` is the stub when built without wallet.
- `libpalladiumqt` — GUI in `src/qt/`; talks to the node through `src/interfaces/` (Node/Wallet/Chain), not directly.
- `src/leveldb`, `src/secp256k1`, `src/univalue`, `src/crc32c` are vendored subtrees — don't edit them (see `test/lint/lint-submodule.sh` / `git-subtree-check.sh`).

## Palladium-specific divergences from Bitcoin Core

Keep these in mind when merging upstream changes or touching consensus/policy code:

- **Chain params** (`src/chainparams.cpp`): mainnet port 2333 (testnet 12333), bech32 HRP `plm` / `tplm`, custom message start bytes. Consensus fields added in `src/consensus/params.h`: `nResilienceForkHeight` (mainnet 340000) and `nPowTargetSpacingV2` (2 min blocks after the fork; on mainnet `nPowTargetSpacing` stays 10 min and `nPowTargetTimespan` 14 days for historical validation; testnet and regtest set `nPowTargetSpacing` to 2 min since both use LWMA from genesis (no legacy retarget). `nPowTargetSpacing` is also read by `DifficultyAdjustmentInterval()` and the timeouts in `net_processing.cpp`, so don't change it on mainnet).
- **Difficulty** (`src/pow.cpp`): before the resilience fork the legacy retarget applies; from `nResilienceForkHeight` it retargets every 60 blocks; testnet (`fPowAllowMinDifficultyBlocks`) uses LWMA (`LwmaCalculateNextWorkRequired`) from genesis. Changes here are consensus-critical.
- **Policy gated on the fork**: OP_RETURN size limit pre-fork (`validation.cpp`, `bad-txns-oversize-opreturn-prefork`).
- **Taproot** activates on mainnet at height 405000 (`TaprootHeight`) plus a BIP9 deployment (`DEPLOYMENT_TAPROOT`, bit 2, Feb 2026–Mar 2027). Segwit/BIP34/65/66/CSV all activate at height 29000. Docs: `doc/TAPROOT.md`, `doc/taproot-guide.md`.
